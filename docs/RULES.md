## Project build folders

Found by one walk of the home folder. Each one is checked against its project: marker file, git tracked or ignored, lock file, last edit, and programs that use it now.

| Folder | Base level | Needs marker | Must be git-ignored | Why | Restore |
|---|---|---|---|---|---|
| `node_modules` | safe | package.json | false | npm, yarn or pnpm installs these packages again from the lock file. | npm ci, yarn install or pnpm install |
| `target` | safe | Cargo.toml, pom.xml, build.sbt | false | Cargo, Maven or sbt writes build output here. | cargo build, mvn package or sbt compile |
| `build` | safe | build.gradle, build.gradle.kts, package.json, CMakeLists.txt, setup.py, pyproject.toml, *.xcodeproj, Podfile, pubspec.yaml | true | The build tool writes its output here. | Run the build again. |

## Dynamic checks

- Every folder in `~/Library/Caches` and `~/.cache` that no rule above claims.
- Chromium and Electron caches inside each app in `~/Library/Application Support` (HTTP, code, GPU and shader caches are safe; service worker storage is review).
- Editor workspace state for folders that no longer exist, and extension versions that `extensions.json` does not list.
- Git worktrees: uncommitted changes, unpushed commits, missing main repository.
- Apps over 200 MB not opened for 90 days (Spotlight), with the Xcode and `xcode-select` dependency.
- Downloads over 100 MB: age, source URL, installers that are already installed, archives already extracted.
- Container runtimes: VM disk images, and `docker system df` when a daemon answers.
- Homebrew `cleanup -n`, APFS local snapshots, deleted files that programs still hold open, the temporary folder.
- Large single files and bundles that no other finding explains.
